# EC2 Infrastructure with ALB and Nginx

**Feature ID**: 002-ec2-alb-nginx  
**Branch**: 002-ec2-alb-nginx  
**GitHub Issue**: #37  
**Status**: Code Generation Complete ✓

## Overview

A highly available, secure web infrastructure using EC2 instances with Nginx web servers distributed across 2 availability zones (ap-southeast-1a and ap-southeast-1b), fronted by an Application Load Balancer with HTTPS termination using a self-signed TLS certificate.

## Architecture

```
Internet
    ↓
[Application Load Balancer]
    ↓ HTTPS (443)
    ↓ TLS Certificate (web.demo.com)
    ↓
    ├──→ [EC2 Instance - AZ1] (t3a.micro, Nginx)
    └──→ [EC2 Instance - AZ2] (t3a.micro, Nginx)
         ↓ HTTP (80)
         └─ [Target Group with Health Checks]
```

## Infrastructure Components

- **2 EC2 Instances**: t3a.micro instances across 2 AZs running Nginx
- **1 Application Load Balancer**: HTTPS listener with TLS 1.3 encryption
- **2 Security Groups**: ALB (HTTPS ingress) and EC2 (HTTP from ALB only)
- **1 Self-signed TLS Certificate**: Generated by Terraform, imported to ACM
- **1 Target Group**: HTTP health checks on port 80

## Deployment

### Prerequisites

- HCP Terraform account with workspace configured
- AWS credentials configured in HCP Terraform workspace
- Terraform >= 1.5.7

### Quick Start

```bash
# 1. Review configuration
cd /workspace
terraform plan

# 2. Deploy infrastructure
terraform apply

# 3. Get ALB DNS name
terraform output alb_dns_name

# 4. Test HTTPS access
curl -k https://<alb-dns-name>
```

## Features

### High Availability
- Instances distributed across 2 availability zones
- ALB health checks with automatic failover
- Zero downtime during single instance failure

### Security
- HTTPS-only access (TLS 1.3)
- Self-signed certificate for web.demo.com
- Security groups with least privilege access
- No direct public access to EC2 instances
- IAM instance profiles for secure AWS API access

### Cost Optimization
- T3a.micro instances (burstable, cost-effective)
- Default VPC usage (no additional networking costs)
- No Elastic IPs or NAT Gateways
- EBS volumes: 8GB GP3 (minimal cost)

### Module-First Architecture
All infrastructure uses approved private registry modules:
- `app.terraform.io/ravi-panchal-org/ec2-instance/aws` (v6.1.4)
- `app.terraform.io/ravi-panchal-org/alb/aws` (v10.2.0)
- `app.terraform.io/ravi-panchal-org/security-group/aws` (v5.3.1)

## Testing

### Browser Access

1. Get ALB DNS name: `terraform output https_url`
2. Open in browser: `https://<alb-dns-name>`
3. Accept self-signed certificate warning
4. Verify Nginx test page with instance metadata

### Command Line Testing

```bash
# HTTPS access
curl -k https://<alb-dns-name>

# TLS certificate verification
openssl s_client -connect <alb-dns-name>:443 -servername web.demo.com

# Health check
aws elbv2 describe-target-health \
  --target-group-arn $(terraform output -raw target_group_arn)
```
